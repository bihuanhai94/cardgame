# 牌桌 UI 参考实现

1 期界面的定稿参考。用浏览器直接打开 `demo.html` 可看完整一手德州的效果
（发牌 → 四轮下注 → 摊牌 → 收池），含筹码物理、音效与牌背花纹。

这些文件是**设计参考**，不是生产代码 —— 1 期实现时把其中的逻辑移植进
React 组件（`packages/web/src/ui/`），并接上真实的引擎状态。

## 文件

| 文件 | 内容 |
|---|---|
| `chips.css` | 筹码本体（俯视扁椭圆 + 侧壁厚度）、码摞、乱堆、落下动画 |
| `chips.js` | 面额拆分、`renderPile`（码摞）、`createHeap`（累积式底池）、`flyChips`（飞行）、`rollTo`（数字滚动） |
| `sfx.js` | 全部 WebAudio 实时合成的音效，不加载任何音频文件 |
| `demo.html` | 完整一手牌的脚本化演示，含座位布局与牌背花纹 |

## 移植时必须保留的几条

1. **筹码本体绝不做 2D 旋转** —— 它是压扁的椭圆，一转就"立起来"了。
   凌乱感只能靠 `--spin` 转表面条纹。
2. **底池是累积的，不是按总额重算的** —— 飞过去哪几枚面额，池子就收下哪几枚，
   否则颜色会在落地瞬间跳变。
3. **底池只追加 DOM 节点，不整堆重建** —— 层叠靠显式 `z-index` 而非 DOM 顺序，
   所以追加不会打乱压盖关系。重建会让整堆"闪一下"。
4. **筹码落点只依赖自身序号**，不依赖池子总数 —— 否则每次加钱都会挤动已有筹码。
5. **玩家自己的筹码码成摞，底池是乱堆** —— 真牌桌就是这样，没人会去码池子。
6. **音效全部合成、不加载文件** —— 部署机出站带宽仅约 4.5 Mbps 且与其他服务共享。
